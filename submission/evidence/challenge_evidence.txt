Analysis & Root Cause:
The `rag_slow` incident simulates latency spikes in Vector Store retrievals by calling `time.sleep(2.5)`. Because FastAPI route handler `/chat` is an `async def` function running on the main event loop, synchronous blockings like `time.sleep` completely lock the event loop, forcing requests to execute sequentially in a Head-of-Line blocking manner. Thus, individual requests internal processing takes ~2.65s (2.5s RAG + 150ms LLM), but clients observe up to 13.3s because of waiting in the Event Loop queue.
